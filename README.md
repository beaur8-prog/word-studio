# Word Studio

Windows용 로컬 문서 편집기입니다. 한국어 리본, 서식 편집, 표·그림·메모, DOCX 변환과 PDF 출력을 제공합니다. Microsoft Word의 화면과 배포 파일 구조를 관찰해 독립적으로 구현했습니다.

## 실행

Node.js 22.12 이상이 필요합니다. 저장소를 내려받은 폴더에서 실행하세요.

```powershell
npm ci
npm run build
npm start
```

브라우저 개발 모드는 `npm run dev`로 실행하며 주소는 `http://127.0.0.1:5191`입니다. 개발 중 데스크톱 앱은 별도 터미널에서 `npm start -- --dev`로 엽니다.

```powershell
npm run package:win
```

Windows x64 포터블 폴더를 `release/windows/Word Studio`에 생성합니다. 공식 Electron 런타임 다운로드와 체크섬 검증을 수행합니다. 실행 중인 이전 배포본은 종료한 뒤 다시 패키징하세요. 실행 파일만 옮기지 말고 폴더 전체를 이동해야 합니다. 배포본 실행에는 Node.js, Office 또는 인터넷 연결이 필요하지 않습니다.

## 1.1.0 개선

- **출력 미리보기**: 보기 → 인쇄 미리보기에서 PDF·인쇄에 사용하는 페이지를 확인합니다. 긴 문단은 문자 결합 단위를 보존하며 나누고, 표는 행 단위로 나누면서 머리행을 반복합니다. 미리보기와 PDF가 같은 페이지 트리를 사용합니다.
- **DOCX 보존**: 구역별 A4/Letter·세로/가로·머리글·바닥글과 방향별 여백을 가져오고 내보냅니다. 검토 메모의 위치·내용·해결 상태도 왕복 보존합니다. 같은 문장이 반복돼도 메모 위치를 텍스트 검색으로 추정하지 않습니다.
- **본문에 연결된 메모**: 본문 편집 시 메모 표시가 이동하고, 메모 창의 ‘본문으로 이동’으로 해당 범위를 선택할 수 있습니다.
- **파일 기반 복구**: 데스크톱에서는 사용자 데이터의 `recovery` 폴더에 원자적 파일 교체로 저장합니다. 문서마다 고유 ID를 사용하므로 제목이 같아도 분리됩니다. 직전 버전은 파일 메뉴에서 복사해 열 수 있습니다. 브라우저에서는 IndexedDB를 사용합니다.
- **종료 보호**: 자동 저장이 진행 중이거나 실패한 상태에서는 종료 확인을 표시합니다. 기존 localStorage 문서는 처음 실행할 때 복구 저장소로 이전합니다.

## 기능

- 홈·삽입·디자인·레이아웃·검토·보기·표 레이아웃 리본
- 글꼴, 크기, 색상, 강조, 제목 스타일, 정렬, 들여쓰기, 줄 간격, 목록
- 표 삽입, 행·열 추가/삭제, 셀 병합/분할, 열 너비 변경
- 로컬 그림, 링크, 날짜, 기호, 페이지 나누기
- 제목 탐색, 찾기·바꾸기, 메모·해결 상태, 읽기 모드
- 자체 `.wordstudio` 형식, DOCX, HTML, TXT, PDF
- 어두운/밝은 화면, 눈금자, 40–200% 확대/축소

Ctrl+N 새 문서, Ctrl+O 열기, Ctrl+S 파일 저장, Ctrl+P 인쇄, Ctrl+F 찾기, Ctrl+Shift+K 명령 검색을 지원합니다.

## 저장과 호환성

편집 상태의 백업에는 `.wordstudio` 형식을 사용하세요. 자동 저장은 현재 PC의 복구 수단이며 별도 파일 백업을 대체하지 않습니다. 최근 문서와 이전 정상 버전 목록에는 최근 20개 문서를 표시합니다. 복구 파일은 앱 사용자 데이터에 남습니다.

편집 화면의 페이지 배치는 블록 단위의 근사치입니다. **최종 출력 페이지는 인쇄 미리보기에서 확인하세요.** 서로 다른 구역의 용지 설정도 출력 미리보기에 적용됩니다. 한 페이지보다 큰 병합 셀 묶음·목록 항목·그림은 잘리지 않게 축소하며 미리보기에 안내를 표시합니다. Word와 동일한 조판 알고리즘이나 완전한 WYSIWYG 편집을 제공하지는 않습니다.

DOCX 가져오기에는 Mammoth를 사용합니다. 모든 글꼴·스타일 속성, 도형·텍스트 상자, 첫 장/짝수 장 전용 머리글, 복잡한 필드, 변경 내용 추적, 매크로와 수식을 완전히 재현하지 않습니다. 연속·홀수·짝수 구역 나눔은 새 페이지 구역으로 정규화합니다. 메모 작성자·답글 계층은 현재 모델에서 유지하지 않습니다. 변환 문서는 원본과 별도로 검토하세요.

## 검증

```powershell
npm run build
npm test
npm run test:native
npm run test:desktop
```

브라우저 테스트는 기본적으로 설치된 Chrome을 사용합니다. 데스크톱 검증은 Windows에서 별도 사용자 프로필과 합성 문서를 사용하며 실제 PDF의 페이지 수와 미리보기를 비교합니다. 결과는 `.cache/desktop-smoke-*`에 저장됩니다. 상세 범위는 [VALIDATION.md](VALIDATION.md)를 참고하세요.

## 분석 근거와 범위

REA/Ghidra로 Word 실행 파일의 시작 함수 3개와 WWLIB의 진입점·헬퍼 영역 6개를 분석했습니다. 실행 파일이 WWLIB의 `FMain`으로 제어를 넘기며, WWLIB에는 줄·페이지·글꼴 배치 관련 외부 모듈의 정적 의존성이 있습니다. 이 관찰을 바탕으로 출력 레이아웃·문서 변환·복구 저장을 별도 모듈로 구현했습니다.

WWLIB 전체 분석이나 Word의 내부 편집·조판 알고리즘 복원은 완료하지 않았습니다. 원본 실행 파일, DLL, 디컴파일 결과, 사용자 문서와 로컬 조사 자료는 이 저장소에 포함하지 않습니다. 앱 코드와 종이·연필 아이콘은 독립적으로 작성했습니다.

기반 편집기는 [Tiptap](https://tiptap.dev/), DOCX 생성은 [docx](https://docx.js.org/), 가져오기는 [Mammoth](https://github.com/mwilliamson/mammoth.js)를 사용합니다. Microsoft와 관련 없는 독립 앱입니다.
